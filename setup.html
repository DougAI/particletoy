particletoy — setup guide

What already works, and the (optional) steps to host it and enable the community gallery.

Works right now, no setup at all:

  • The full editor — emitters, curves, gradients, PBR materials, shader editor
  • Both graphics pipelines (deferred & forward), G-buffer debug views
  • Share — the entire effect is compressed into the URL itself, no server involved
  • Save / Library — effects stored in your browser (localStorage)
  • Export / Import — effects as portable .particletoy.json files

The only feature that needs infrastructure is the public community gallery (the Publish button) — see step 3.

1Run it locally

particletoy is a fully static app (plain ES modules, zero dependencies, no build step), but browsers refuse to run ES modules from file:// — so serve the folder over HTTP. A ready-made dev server is included:

cd C:\projects\particletoy
python serve.py            # then open http://localhost:8917

Any static server works instead (npx serve, npx http-server, nginx, …). One caveat on Windows: plain python -m http.server reads MIME types from the registry and often serves .js as text/plain, which breaks ES modules — serve.py exists precisely to pin the correct types.

Browser requirements: WebGL2 + EXT_color_buffer_float (HDR render targets). Every current Chrome / Edge / Firefox / Safari qualifies; the app shows a clear error message if something is missing.

2Host it (free static hosting)

Because there's no build step and no backend, hosting is just "upload the folder". Share links keep working on any host since the effect data lives in the URL fragment.

Option A — GitHub Pages (recommended)

cd C:\projects\particletoy
git init
git add -A
git commit -m "particletoy"
gh repo create particletoy --public --source . --push
gh api -X POST repos/{owner}/particletoy/pages -f build_type=workflow 2>$null
# or simply: repo Settings → Pages → Deploy from branch → main / (root)

Your app appears at https://<you>.github.io/particletoy/ in a minute or two.

Option B — Netlify / Cloudflare Pages / Vercel

  • Drag-and-drop the folder onto netlify.com/drop, or
  • Connect the repo in the dashboard; set build command: none, publish directory: /.

You can delete serve.py and _shots/ before deploying — they are development helpers only.

3Enable the community gallery (optional)

The Publish / gallery feature needs a tiny database. The app ships with a complete Supabase integration (plain REST, no SDK) that is dormant until you fill in two constants. Total setup ≈ 5 minutes on the free tier.

3.1 Create the project & table

  • Create a free project at supabase.com/dashboard
  • Open SQL Editor and run:
create table public.effects (
  id         uuid primary key default gen_random_uuid(),
  created_at timestamptz not null default now(),
  name       text not null check (char_length(name) between 1 and 80),
  author     text not null check (char_length(author) between 1 and 40),
  data       jsonb not null check (pg_column_size(data) < 200000)
);

alter table public.effects enable row level security;

-- anyone may read and publish; nobody may edit or delete via the anon key
create policy "public read"    on public.effects for select using (true);
create policy "public publish" on public.effects for insert with check (true);

3.2 Paste your keys

In Project Settings → API, copy the Project URL and the anon public key, then open js/backend.js and fill in the two constants at the top:

const SUPABASE_URL = 'https://YOURPROJECT.supabase.co';
const SUPABASE_ANON_KEY = 'eyJhbGciOi…';

That's it — the Publish button now uploads to your gallery, the publish dialog lists recent community effects, and ?id=<uuid> URLs load published effects directly.

The anon key is designed to be public — the RLS policies above are what limit it to read + insert. For real public deployments consider adding Supabase's rate limiting, a moderation flag column, or captcha at the edge.

4Where things live

index.html        app shell
setup.html        this guide
serve.py          dev server (correct MIME types + screenshot helper)
css/style.css     theme
js/
  main.js         bootstrap, frame loop, toolbar
  renderer.js     deferred + forward PBR pipelines, bloom, tonemap
  shaderlib.js    GLSL library + user-shader wrappers (the material API)
  particles.js    emitters: spawn/burst/loop, curves, instancing
  materials.js    material model + per-variant compilation
  presets.js      built-in example effects
  ui.js           inspector, shader editor panel, modals
  editor.js       GLSL code editor (highlighting, errors)
  widgets.js      curve + gradient canvas editors
  curves.js       curve/gradient models, LUT baking
  geometry.js     quad/cube/sphere meshes + OBJ parser
  camera.js       orbit camera
  share.js        URL sharing, JSON export, localStorage library
  backend.js      community gallery (Supabase REST) — configure in step 3
  glutil.js / math3d.js   WebGL2 + math helpers

Have fun. The ? button in the editor documents the full shader API (PBR Surface struct, particle inputs, noise library).
